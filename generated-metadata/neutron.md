# Additional Metadata

## Clarified Semantics

- Two independent LBaaS generations coexist: legacy Neutron LBaaS v1 tables (`pools`, `vips`, `members`, `healthmonitors`, `sessionpersistences`, `poolmonitorassociations`, `poolstatisticss`) and LBaaS v2 tables (`lbaas_loadbalancers`, `lbaas_listeners`, `lbaas_pools`, `lbaas_members`, `lbaas_healthmonitors`, `lbaas_loadbalancer_statistics`, `lbaas_loadbalanceragentbindings`). Each has its own `pool` concept with distinct IDs; do not conflate them.
- `standardattributes` is the shared resource-attribute backbone: 1:1 (`standard_attr_id`) with `networks`, `ports`, `routers`, `subnets`, `subnetpools`, `securitygroups`, `securitygrouprules`, and `floatingips`. It carries common `created_at`/`updated_at`/`description` used by all these resources.
- `ports.device_owner` encodes the consumer: `compute:nova`/`compute:None` (VM), `network:dhcp`, `network:floatingip`, `network:router_interface`, `network:router_gateway`, `neutron:LOADBALANCERV2`/`neutron:LOADBALANCER` (LBaaS). `device_id` holds the owning instance/router/LB UUID.
- `floatingips` is fully double-ported: `floating_port_id` is the port on the external network (unique per floating IP), `fixed_port_id` (nullable) is the internal port it maps to; 13 of 23 rows are unbound (DOWN, no fixed port). `floating_network_id` is always the single external network.
- `ml2_network_segments` describes how each `networks` row is realized (network_type `gre`/`vlan`, physical_network, segmentation_id); `ml2_port_binding_levels.segment_id` links each port's host binding to that segment.
- `ipallocations` (3,779 rows) is the actual IP-to-port mapping per (port, subnet, network); a port can hold multiple allocations and one row has a null port. `ipallocationpools`/`ipavailabilityranges` define the allocatable pools; `ipavailabilityranges` is a sub-range breakdown of a pool.
- Agent binding tables are effectively 1:N hubs: all `networkdhcpagentbindings` rows point to one DHCP agent, all `routerl3agentbindings` to one L3 agent, all `lbaas_loadbalanceragentbindings` to one LBv2 agent. `agents.agent_type`/`binary`/`topic` classify agent role (`agent_type` is the source of truth).
- `networkrbacs` are network RBAC policies (`object_id`→`networks.id`), with `action` `access_as_shared` vs `access_as_external` and `target_tenant` of `*` meaning all tenants; `externalnetworks` separately flags a default external network (`is_default`).
- `routerports` is the authoritative router↔port membership with `port_type` (`network:router_interface` vs `network:router_gateway`), complementing the denormalized per-port `device_owner`/`device_id` values.
- Two quota systems: `quotas` (configured per-tenant limits per resource) and `quotausages` (current `in_use`/`reserved`/`dirty` counters per resource). `quotas.resource` includes legacy v1 `pool`/`rbac_policy` besides the standard v2 resources.
- `ml2_vlan_allocations`/`ml2_gre_allocations` are provider-segment allocation pools (`allocated=1` used, `=0` free); `physical_network` links vlan entries to `ml2_network_segments.physical_network`.
- `portsecuritybindings` (per-port) and `networksecuritybindings` (per-network) both carry `port_security_enabled`; `securitygroupportbindings` is the many-to-many association of security groups to ports.

## Potential Join Strategies

- Port → network → segment: `ports.network_id = networks.id`, then `ml2_network_segments.network_id = networks.id`; filter `network_type`/`physical_network`/`segmentation_id`. Every port also has an `ml2_port_binding_levels` row (`segment_id`) giving its host and driver mapping.
- IP lineage: `ports.id` → `ipallocations.port_id` (multiple per port), `ipallocations.subnet_id`→`subnets.id`, `ipallocations.network_id`→`networks.id`; `ipallocationpools.subnet_id`→`subnets.id` and `ipavailabilityranges.allocation_pool_id`→`ipallocationpools.id` for the address-pool subtree.
- Floating IP resolution: `floatingips.fixed_port_id`/`floating_port_id`→`ports.id`, `floatingips.router_id`→`routers.id`, and `floatingips.floating_network_id`→`networks.id` (always the external network). Join on (port, router) to trace a floating IP to its bound VM and its gateway router.
- Router topology: `routers.id`→`routerports.router_id`→`ports.port_id` with `port_type` to split gateway vs interface ports; `routers.gw_port_id`→`ports.id` gives the gateway directly. `routerl3agentbindings`/`router_extra_attributes` add agent placement and HA/distributed flags.
- Common metadata: join any resource table to `standardattributes` on `standard_attr_id` for uniform timestamps/description (e.g., `networks`, `ports`, `routers`, `subnets`, `securitygroups`, `floatingips`).
- Security group to port: `securitygroupportbindings` (port_id, security_group_id) joins both to `ports` and `securitygroups`; `securitygrouprules` join on `security_group_id` (owner) and `remote_group_id` (peer group) to analyze intra-tenant peer rules and default (`default_security_group`) groups.
- LBaaS v2 chain: `lbaas_loadbalancers`→`lbaas_listeners` (loadbalancer_id)→`lbaas_pools` (default_pool_id)→`lbaas_members` (pool_id); bind to `agents` via `lbaas_loadbalanceragentbindings` and to ports via `lbaas_loadbalancers.vip_port_id`. Watch 1:N fan-out at listeners/members. Legacy v1 chain analogous: `pools`→`vips.pool_id`/`members.pool_id`/`poolmonitorassociations`/`poolstatisticss`; `vips.port_id`→`ports.id`.
- Agent affinity: `agents.id` is the hub for `networkdhcpagentbindings.dhcp_agent_id`, `routerl3agentbindings.l3_agent_id`, and `lbaas_loadbalanceragentbindings.agent_id` — join to attribute networks/routers/LBs to a given agent; each binding is effectively 1:1 with one agent (DHCP and LB agents are each a single shared agent in this dataset).
- Host-based fan-out: `ml2_port_bindings.host` and `ml2_port_binding_levels.host` both keyed on `ports.id`; `agents.host` and `ml2_gre_endpoints.host` give agent/endpoint hosts. Join on `host` string to correlate which ports sit on which compute/agent host — note `host` is a coarse string key with high cardinality (120+ distinct).
- Tenant cross-cutting: all core tables carry `tenant_id`, so join `ports`/`routers`/`networks`/`subnets`/`securitygroups`/`floatingips` on `tenant_id` for per-tenant profiles; `quotas`/`quotausages` provide limits vs actual usage per `tenant_id`. No tenant dimension table exists — tenant is a string column only.
- Network RBAC/external reach: `networkrbacs.object_id`→`networks.id` with `action`/`target_tenant` to find shared/external-accessible networks; cross-check `externalnetworks.network_id` for the marked default external network (only one such network in this dataset).
