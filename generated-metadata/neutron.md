# Additional Metadata

## Clarified Semantics

- Two independent load-balancer generations coexist. `lbaas_*` tables (agents `Loadbalancerv2 agent`, topic `n-lbaasv2_agent`) are LBaaS v2; `pools`/`members`/`vips`/`healthmonitors`/`poolmonitorassociations`/`poolstatisticss`/`sessionpersistences` are the legacy v1 hierarchy. Do not join the two pools chains on shared column names; they are distinct `pools.id` vs `lbaas_pools.id` namespaces.
- `providerresourceassociations` is a generic registry keyed by `provider_name` ("haproxy"); its `resource_id` (UNIQUE) does NOT point to one table. Verified resource_id values resolve to both `lbaas_loadbalancers` (v2) and `pools` (v1) rows, so it should be used as a loose existence/ownership filter, not a strict FK join.
- `floatingips.floating_port_id` is the port created for the floating IP itself (in the `floating_network_id` external network); `floatingips.fixed_port_id` points to the instance port being floated. Null `fixed_port_id`/`router_id`/`fixed_ip_address` rows are `status='DOWN'` (unbound) floaters (13 of 23).
- `floatingips.last_known_router_id` is a separate, nullable pointer to `routers.id` (retained routing hop after disassociation), distinct from `router_id`.
- `ipallocations` denormalizes the owning network: `network_id` duplicates `subnets.network_id`. Note one sample row shows a stray `ip_address` value (`track`) that is not a real address.
- `standardattributes` is a sharded metadata table shared by floatingips, networks, ports, routers, securitygrouprules, securitygroups, subnetpools, subnets, and tags, discriminated by `resource_type`. Its `id` is a global counter, not per-type-unique.
- `default_security_group` maps each `tenant_id` to its default `securitygroup`, so it can be used to tell whether a group is a tenant's default.
- `routers.enable_snat=1` for all 27 rows; `router_extra_attributes` holds `distributed`/`service_router`/`ha`/`ha_vr_id` flags (all 0 here).
- `ports.device_owner` is the authoritative indicator of port role: `compute:*` (instances), `network:dhcp`, `network:floatingip`, `network:router_interface`/`router_gateway`, `neutron:LOADBALANCERV2`. `redirect` filter: ~2700 `status='DOWN'`, `device_id` mostly unused naming.
- `agents.topic` is empty for 126 rows and only set for the single DHCP/L3/LBv2/metadata agents; `agent_type`+`host` is UNIQUE, and `host` doubles as the physical hypervisor/tunnel host key.
- `ml2_port_bindings.vif_type` distinguishes bound (`ovs`, 3692) vs `unbound`/`binding_failed`; `host` is the compute node where the port is bound.
- `ml2_network_segments.network_type` is only `gre` (42) or `vlan` (7) here; `physical_network='trunk'` appears only on vlan segments.
- `pools.subnet_id` and `lbaas_loadbalancers.vip_subnet_id` / `lbaas_members.subnet_id` are not declared FKs but reference `subnets.id`.

## Potential Join Strategies

- Port → segment → network: `ml2_port_binding_levels.port_id = ports.id` AND `segment_id = ml2_network_segments.id`, then `ml2_network_segments.network_id = networks.id` reveals the concrete segmentation (gre/vlan) backing a tenant port. Filter `ml2_port_binding_levels.level = 0` (all rows are level 0). `ml2_port_binding_levels.segment_id` is nullable.
- Port placement/agent: `ml2_port_binding_levels.host` (or `ml2_port_bindings.host`) = `agents.host` to see which Open vSwitch agent (`agent_type='Open vSwitch agent'`) serves a port; also `ml2_gre_endpoints.host` → `agents.host` to map tunnel endpoints to agents (gre_endpoints.host nullable).
- Per-network agent bindings are 1-N junction tables: `networkdhcpagentbindings(network_id ↔ dhcp_agent_id)`, `routerl3agentbindings(router_id ↔ l3_agent_id)`, `lbaas_loadbalanceragentbindings(loadbalancer_id ↔ agent_id)`; all → `agents.id`. Constrain on `agents.agent_type`/`topic` to avoid cross-role collisions (e.g., only the L3 agent row has `topic='l3_agent'`).
- Floating IP chain: `floatingips.floating_port_id = ports.id` (floating side) and `floatingips.fixed_port_id = ports.id` (instance side) resolve the two-port model; `floatingips.floating_network_id = networks.id` is inferred (not declared) and `router_id`/`last_known_router_id` → `routers.id`. Join only on rows where `fixed_port_id` is non-null to scope to bound floaters.
- IP-to-round-trip: find an allocated address by joining `ports.id = ipallocations.port_id`, then `ipallocations.subnet_id = subnets.id` and `subnet_id = ipallocationpools.subnet_id`; `ipavailabilityranges.allocation_pool_id = ipallocationpools.id` gives the full-range sub-slices for capacity. `ipallocations.network_id` shortcut avoids the subnets hop but duplicates it.
- LBaaS v2 topology: `lbaas_loadbalancers.id ← lbaas_listeners.loadbalancer_id ← lbaas_l7policies.listener_id ← lbaas_l7rules.l7policy_id`; `lbaas_listeners.default_pool_id → lbaas_pools.id`; `lbaas_pools.loadbalancer_id` back to LB; `lbaas_pools.healthmonitor_id → lbaas_healthmonitors.id` (UNIQUE). Note `lbaas_listeners` has a UNIQUE `(loadbalancer_id, protocol_port)` constraint — one listener per LB-port.
- LBaaS v2 members/load: `lbaas_members.pool_id → lbaas_pools.id`, plus `lbaas_pools.subnet_id`/`lbaas_members.subnet_id` → `subnets.id`. Statistics are separate `lbaas_loadbalancer_statistics(loadbalancer_id)` rows (6) not tied to listeners/pools.
- Legacy v1 chain: `pools.id ← members.pool_id`, `pools.vip_id → vips.id`, `vips.pool_id` back (UNIQUE), `vips.port_id → ports.id`, `pools.id ← poolmonitorassociations.pool_id` with `poolmonitorassociations.monitor_id → healthmonitors.id`, and counters in `poolstatisticss.pool_id` (1:1).
- Port security-groups: `securitygroupportbindings.port_id → ports.id` and `security_group_id → securitygroups.id`; then `securitygrouprules.security_group_id` (and `remote_group_id` self-FK to `securitygroups.id`) to enumerate rules governing a port. `securitygrouprules.remote_group_id` is null in ~7266 rows (CIDR-based rules).
- Quota usage vs limit: `quotas(tenant_id, resource)` join `quotausages(tenant_id, resource)` on both keys to compare `limit` vs `in_use`. `quotausages.reserved` is always 0; `dirty=1` (152 rows) marks rows awaiting recalculation.
- Security-rule delivery to ports via default group: `securitygroupportbindings.security_group_id` can be traced through `default_security_group.tenant_id` to identify whether applied rules come from a tenant's default chain.
- Reservation accounting: `reservations.id ← resourcedeltas.reservation_id`, with `resourcedeltas.resource='port'` and `amount`; all 5 reservations belong to one tenant.
- Shared/external networks via RBAC: `networkrbacs.object_id → networks.id`; `action='access_as_shared'` (13) vs `access_as_external` (1) vs `target_tenant='*'`.
- SHARED/EXTERNAL flag tables are 1:1 with networks: `externalnetworks.network_id` and `networksecuritybindings.network_id` (both PK on the network id).
