# Additional Metadata

## Clarified Semantics

- The `shadow_*` tables are soft-delete archives: rows that were removed from the corresponding live tables (e.g. `instances`, `block_device_mapping`, `instance_actions`, `reservations`, `fixed_ips`) are moved there with a `deleted` marker. They carry no foreign keys, so any join through them must be done on UUID values only.
- `all_instances` is a view that `UNION ALL`s `instances` and `shadow_instances`; `instances.deleted` is a soft-delete flag where non-zero values are internal delete markers, not row counts.
- `instances.instance_type_id` has no FK but references `instance_types.id`; `instances` also denormalizes its own copy of `memory_mb`, `vcpus`, `root_gb`, `ephemeral_gb` from the flavor at launch time (so the two may diverge after a resize).
- `instances.host`/`instances.node`/`instances.launched_on` all identify the compute host but at different granularities: `host` is the short name (e.g. `cosmo3-23`), `node` is the FQDN form (`cosmo3-23.yahoo.ca.com`) matching `compute_nodes.hypervisor_hostname`, and `launched_on` is the short host at launch. `host`/`node` are empty for unscheduled instances.
- `compute_nodes.host` (short name) and `compute_nodes.hypervisor_hostname` (FQDN) both identify a node; several rows share a host with different hypervisor_hostnames, and there are rows with empty `host`.
- `instance_group_member.instance_id` is a varchar holding an instance UUID (despite the column name `instance_id`), joining to `instances.uuid`; matches only a subset of the group memberships (many target deleted/archived instances).
- `pci_devices.status`/`instance_uuid`/`request_id` track device assignment: currently all rows are `available` with NULL `instance_uuid`, so `pci_devices` describes inventory, not active allocations.
- `block_device_mapping` rows are per block device of an instance; `source_type` (`volume`/`image`/`blank`/`snapshot`) and `destination_type` (`volume`/`local`) define the device origin, and `image_id`/`volume_id`/`snapshot_id` only populate one depending on source.
- `quota_usages`/`reservations`/`quotas` track quota accounting with `reservations.delta` being signed (positive=reserve, negative=commit/release); `reservations.deleted` is a soft-delete non-zero marker.

## Potential Join Strategies

- **Instance flavor**: `instances.instance_type_id = instance_types.id` — resolve the flavor (name, vcpus, memory_mb, root_gb, ephemeral_gb) for sizing/grouping. Caveat: `instances` stores a copy of these dimension columns, so prefer the denormalized instance columns when you need the flavor as-launched, and join `instance_type_extra_specs.instance_type_id` for extra specs only on the non-deleted rows.
- **Compute node to service**: `compute_nodes.service_id = services.id` where `services.binary='nova-compute'` — attach service `host`, `disabled`, `disabled_reason`, `last_seen_up`, `version` to capacity metrics. Caveat: `compute_nodes.service_id` is NULL on some rows and `services` may hold multiple binaries per host; filter on the compute binary.
- **Instance to node capacity**: `instances.node = compute_nodes.hypervisor_hostname` (with `compute_nodes.deleted=0`) — correlate running VM placement with per-host usage (`vcpus_used`, `memory_mb_used`, `local_gb_used`, `running_vms`). Caveat: use the `node` column (FQDN), not `host`; unscheduled instances have NULL `node` and are dropped.
- **Instance to PCI inventory**: `pci_devices.compute_node_id = compute_nodes.id`, and `pci_devices.instance_uuid = instances.uuid` — find which nodes carry GPU (`vendor_id='10de'`, `product_id='102d'`) and to which instances they were assigned. Caveat: current `pci_devices.instance_uuid` is all-NULL (all `available`), so the assignment join yields nothing until devices are allocated; `instance_extra.pci_requests` (alias `gpu`) is a complementary signal.
- **Block device to instance**: `block_device_mapping.instance_uuid = instances.uuid` (declared FK) — attach volumes/images per instance. For image-sourced disks, `block_device_mapping.image_id` correlates with `instances.image_ref`; volume and snapshot ids are opaque and only cross-reference outside nova.
- **Network lineage**: `fixed_ips.network_id = networks.id` and `fixed_ips.virtual_interface_id` → virtual interfaces; with `floating_ips.fixed_ip_id = fixed_ips.id` for the fixed↔floating mapping. Caveat: `floating_ips.fixed_ip_id` is currently all-NULL and `networks` has a single row (`id=1`), so floating/fixed joins degrade to the one network; `instance_info_caches.network_info` (JSON) is where live per-instance IPs actually live.
- **Instance to group membership**: `instance_group_member.group_id = instance_groups.id` and `instance_group_policy.group_id = instance_groups.id` (declared), with member `instance_id` joining `instances.uuid` — attribute instances to server groups and their `affinity`/`anti-affinity` policy. Caveat: membership references many archived instances, so count-mismatch unless filtered to live `instances`.
- **Quota audit trail**: `reservations.usage_id = quota_usages.id` (declared FK) links signed reservation deltas to running `in_use`/`reserved` usage per project+resource(+user); join on `project_id`/`resource` to reconcile limits (`quotas.hard_limit`, `quota_classes`). Caveat: `quota_usages` carries both `project_id` and optional `user_id`, so aggregate per project vs per user requires the right grouping level.
- **Security groups**: `security_group_rules.parent_group_id`/`group_id = security_groups.id` (declared; self-referencing) — `group_id` denotes a source-group rule referencing another group, `parent_group_id` the owning group; attribute groups to instances via `security_group_instance_association` when populated. Caveat: `security_group_rules.group_id` is NULL for most rows (CIDR rules dominate).
- **Snapshot lineage**: `block_device_mapping.snapshot_id` and `shadow_snapshots`/`snapshots` share UUID-space with `snapshot_id_mappings.uuid` and `volume_id_mappings.uuid` — these are legacy UUID-mapping tables (all rows non-deleted) that can bridge snapshot/volume UUIDs when only an internal id is available.
