# Additional Metadata

## Clarified Semantics

- `cip` / `cip_with_version`: CIP = US Classification of Instructional Programs. `PROGRAM_CODE` is unique within `cip`; `cip_with_version` stores one row per (PROGRAM_CODE, VERSION), and its composite key `CIP_WITH_VERSION_KEY` is `PROGRAM_CODE` concatenated with `VERSION` (e.g. `99999`+`2020` = `999992020`). `FOUR_DIGIT_CODE` is the rolled-up two-digit/four-digit prefix of `PROGRAM_CODE`.
- Term-code format is `YYYY<FA|SP|SU|JA>`, where `JA` is January/Independent Activities Period (IAP), `SU` summer. `academic_terms` (144 rows / 36 academic years) is the current snapshot; `academic_terms_all` (300 rows / ~80 years) additionally contains obsolete/old terms — join the latter for historical coverage.
- `academic_term_parameter` is a 3-row pointer table: `TERM_PARAMETER` (`SIS_CURRENT_TERM`/`SIS_PREVIOUS_TERM`/`SIS_UPCOMING_TERM`) maps to `TERM_CODE` via `TERM_CODE`, giving a stable way to resolve "current/prior/next" term rather than scanning `IS_CURRENT_TERM`.
- Subject "sort" columns (`SUBJECT_ID_SORT`, `MASTER_SUBJECT_ID_SORT`, `COURSE_NUMBER_SORT`, etc.) are the canonical IDs padded with leading spaces purely for lexical ordering; the unpadded form is `SUBJECT_ID` / `MASTER_SUBJECT_ID` / `COURSE_NUMBER`. Cross-table joins should use the unpadded columns (or trim) to avoid mismatch from differing padding.
- Master/grouping placeholders: `MASTER_SUBJECT_ID` (`HAA.0000`, `HAK.0000`, …) is a cluster/master subject. In `subject_enrollable` and `subject_offered`, every row has the same placeholder `MASTER_SUBJECT_ID`/`ULT_MASTER_SUBJECT_ID` (`HAA.0000`), so those columns are degenerate there — use `SUBJECT_ID` instead.
- `COMPOSITE_SUBJECT_KEY` encodes `MASTER_SUBJECT_ID + TERM_CODE` (e.g. `HAA.00002014JA`) and is shared by `subject_offered` and `subject_offered_summary`.
- `fac_*` and `fclt_*` are parallel pre-2016 (FAC) / current (FCLT) facilities sets; `fclt_*_hist` and `fclt_building_hist_1` are time-sliced snapshots keyed by `FISCAL_PERIOD` (6-digit `YYYYPP`). `fac_building` and `fclt_building` share values but use different key columns (`BUILDING_KEY` vs `FCLT_BUILDING_KEY`).
- `FLOOR_KEY` / `FCLT_FLOOR_KEY` are composite strings `BUILDING-FLOOR` (e.g. `WW15-1`). `SPACE_ID` is `BUILDING-FLOOR-ROOM`. `BUILDING_ROOM` is `BUILDING-ROOM` (e.g. `45-398`).
- `BUILDING_KEY`, `BUILDING_NUMBER`, `FCLT_BUILDING_KEY`, and `BUILDING_COMPONENT` all carry the same building code string; `fac_building_address.BUILDING_KEY` joins to `fac_building`/`buildings` on this code.
- `COST_CENTER_CODE` and `COST_COLLECTOR_KEY` always hold identical values in the facility tables.
- The `subject`/`fclt_organization` facet: `ORGANIZATION_KEY`/`FCLT_ORGANIZATION_KEY` (numeric string) is the facilities org; `FCLT_ORGANIZATION_KEY` doubles as `SPACE_UNIT_KEY` in `space_unit`. `DLC_KEY` (e.g. `D_MECHE`) is the central department/level-1 cost object used across facilities, HR, space, and roles.
- `space_usage.SPACE_USAGE_KEY` maps numeric `space_detail.SPACE_USAGE_KEY` to a usage label; many usage keys resolve to `null` labels.
- Person tables (`employee_directory`, `drupal_employee_directory`, `se_person`, `hr_faculty_roster`, `warehouse_users`, `moira_list_detail`, `space_supervisor_usage`) are all keyed by `MIT_ID`; `KRB_NAME` (username) is an alternate identity. `drupal_employee_directory` is a drupal/web-source subset (HR_ORG_UNIT_* instead of DEPARTMENT_*).
- `moira_list_detail.MOIRA_LIST_OWNER_KEY` prefixed `LIST…`/`USER…` links to `moira_list_owner.OWNER_KEY`; `MOIRA_LIST_MEMBER_MIT_ID` links back to person tables.
- Library reserve chain: `library_reserve_matrl_detail` bridges `library_course_instructor` (instructor + course), `library_reserve_catalog` (bibliographic record, `LIBRARY_RESERVE_CATALOG_KEY` = system number), `library_subject_offered` (`LIBRARY_SUBJECT_OFFERED_KEY`), and `library_material_status`.
- TIP chain: `tip_detail.TIP_SUBJECT_OFFERED_KEY` → `tip_subject_offered`; `TIP_MATERIAL_KEY` → `tip_material`; `TIP_MATERIAL_STATUS_KEY` → `tip_material_status` (RQ=Required, NM=course has no materials, EO=electronic options, RC=Recommended, etc.).
- `time_day` / `time_month` / `time_quarter` are date dimensions exposing `FISCAL_PERIOD` (YYYYPP), `CALENDAR_YEAR`, `ACADEMIC_YEAR`, `FINANCIAL_AID_YEAR`, and `ACADEMIC_TERM_CODE`; `frc_fiscal_periods` is a small 10-row lookup relating fiscal periods to calendar descriptions.
- `fac_rooms`/`fclt_rooms` are heavily skewed: e.g. `fac_rooms.ORGANIZATION_KEY` is `149` (DOF) for 9,090 rows and only ~9 distinct org keys, and `MAJOR_USE` concentrates on CIRCULAT/MECHANIC — distinctness is low, so group-by on these columns collapses most rows.
- `zpm_rooms_load` is a transform/load staging view aligned with `space_detail` (same `BUILDING_ROOM`, `SPACE_UNIT_CODE`).

## Potential Join Strategies

- **Term → catalogue**: join `course_catalog_subject_offered.TERM_CODE` / `EFFECTIVE_TERM_CODE` → `academic_terms.TERM_CODE` to attach start/end dates, `ACADEMIC_YEAR`, `IS_REGULAR_TERM`, `TERM_STATUS`. Use `academic_terms_all` when terms are historic. `drupal_course_catalog.SO_TERM_CODE` and `SO_TERM_DESCRIPTION` give the term at "source" grain.
- **Resolve current/preceding/upcoming term**: `academic_term_parameter` joined to `academic_terms` on `TERM_CODE` (filter `TERM_PARAMETER='SIS_CURRENT_TERM'` etc.), then carry `ACADEMIC_TERMS_KEY`/`TERM_CODE` forward to any `TERM_CODE`-keyed fact table.
- **Subject identity across grains**: join on `SUBJECT_ID + TERM_CODE` (and optionally `SECTION_ID`) between catalogue/summary tables telling the same offerings apart; prefer `SUBJECT_OFFERED_SUMMARY_KEY` / `SUBJECT_SUMMARY_KEY` when both sides carry them (they are equal in `subject_offered` vs `subject_offered_summary`).
- **Master/cluster rollups**: `subject_enrollable.SUBJECT_GROUP_ID` → `subject_summary.SUBJECT_GROUP_ID` to link enrollable offerings to per-term summary enrollment counts; `subject_offered.SUBJECT_GROUPING_KEY` → `subject_grouping.SUBJECT_GROUPING_KEY` to attach DEPARTMENT/SCHOOL and term. Caveat: grouping IDs are opaque hex tokens, so only join on the exact key columns.
- **Same-subject equivalence**: `subject_offered.MASTER_SUBJECT_ID` / `MASTER_SUBJECT_ID_SORT` links lecture/lab/recitation sections and cross-listed subjects that share a master, enabling aggregation to subject level; avoid using `MASTER_SUBJECT_ID` alone inside `subject_enrollable`/`subject_offered` where it is a constant placeholder.
- **CIP linkage**: `sis_course_description.CIP_PROGRAM_CODE` (e.g. `142701`) → `cip.PROGRAM_CODE` for CIP title/category, or → `cip_with_version` on `PROGRAM_CODE` (+ pick `VERSION`) for historical code set. `cip.FOUR_DIGIT_CODE` ↔ `cip_with_version.FOUR_DIGIT_CODE` rolls subject/program CIPs up to four-digit discipline.
- **Facilities hierarchy**: `fclt_rooms.FCLT_FLOOR_KEY` → `fclt_floor` → `fclt_building` (`FCLT_BUILDING_KEY`), and `fclt_rooms.MAJOR_USE`/`FCLT_MAJOR_USE_KEY` → `fclt_major_use` for room-use aggregation; only join hist variants when a `FISCAL_PERIOD` filter is required. `fac_rooms.FLOOR_KEY` → `fac_floor` mirrors this on the legacy side.
- **Space → organization → DLC**: `space_detail.SPACE_UNIT_KEY` → `space_unit`/`space_unit2.SPACE_UNIT_KEY` (also `SPACE_UNIT_CODE`) → `DLC_KEY`; alternatively `zpm_rooms_load.HR_ORG_UNIT_ID` → `hr_org_unit.HR_ORG_UNIT_ID`. This attaches cost-center/org (`DLC`) to physical rooms. `fac_rooms.ORGANIZATION_KEY` → `fac_organization.ORGANIZATION_KEY` uses the facilities org facet instead.
- **Building/room alignment**: `space_detail.BUILDING_ROOM` = `fclt_rooms.BUILDING_ROOM` = `zpm_rooms_load.BUILDING_ROOM`; `space_detail` and `zpm_rooms_load` share 29/34 building components while `fclt_rooms` spans many more buildings — a join on `BUILDING_ROOM` is 1:1-ish only within the matched common buildings and drops non-common buildings.
- **Building ↔ catalog meeting place**: `course_catalog_subject_offered.MEET_PLACE` / `MEET_TIME` contains room tokens like `E51-350`; `fclt_rooms.BUILDING_ROOM` (and building-level keys) can resolve these tokens into building/room/floor, though `MEET_PLACE` is sparse (~5.5k nulls) and free-form (e.g. `VIRTUAL`, `TBA`).
- **People across sources**: join `drupal_employee_directory.MIT_ID` = `employee_directory.MIT_ID` = `se_person.MIT_ID` = `warehouse_users.MIT_ID`; `se_person.KRB_NAME`/`warehouse_users.KRB_NAME` ↔ `person_auth_area.USER_NAME`; `employee_directory.KRB_NAME` links to Kerberos-based lists/mail. Keep `TYPE` (EMPLOYEE vs STUDENT) in `warehouse_users` and `EMPLOYEE_TYPE` in `se_person`/`drupal_employee_directory` to distinguish populations.
- **Faculty org join caveat**: `hr_faculty_roster.MIT_ID` joins person tables on `MIT_ID`, but its `HR_ORG_UNIT_TITLE` is a name — join to `hr_org_unit.HR_ORG_UNIT_TITLE` (not the ID), because `hr_faculty_roster` carries no `HR_ORG_UNIT_ID`.
- **HR units → DLC**: `hr_org_unit.HR_ORG_UNIT_ID` (numeric `1000x…`) joins `drupal_employee_directory.HR_ORG_UNIT_ID`, `fac_organization.HR_ORG_UNIT_ID`, `fclt_organization.HR_ORG_UNIT_ID`, and `zpm_rooms_load.HR_ORG_UNIT_ID`; its `DLC_KEY` then links to `master_dept_hierarchy` (level-2+ parent hierarchy) or `roles_fin_pa` for role-by-DLC.
- **Library course materials**: `library_reserve_matrl_detail.LIBRARY_SUBJECT_OFFERED_KEY` → `library_subject_offered` (to get `TERM_CODE`, `SUBJECT_ID`, `OFFER_DEPT_CODE`, `NUM_ENROLLED_STUDENTS`), and `LIBRARY_COURSE_INSTRUCTOR_KEY` → `library_course_instructor`; filter status via `LIBRARY_MATERIAL_STATUS_KEY` → `library_material_status`.
- **Textbook (TIP) join**: `tip_detail.TERM_CODE + SUBJECT_ID` aligns with `subject_offered_summary`/`subject_summary` to cross-reference textbook status with enrollment; `tip_subject_offered` mirrors `library_subject_offered` (`SUBJECT_ID`, `OFFER_DEPT_CODE`, `RESPONSIBLE_FACULTY_MIT_ID`, `NUM_ENROLLED_STUDENTS`) and can join either side. Filter out `NM`/`N/…` statuses when measuring actual materials; many TIP rows share the generic `N/ACourse…` `TIP_MATERIAL_KEY`.
- **Date dimension**: join any `FISCAL_PERIOD`-keyed hist/fact row to `time_month`/`time_quarter` or `frc_fiscal_periods` for period labels, and to `time_day.CALENDAR_DATE` for day-level academic-term (`ACADEMIC_TERM_CODE`) context.
- **Address/geo joins**: `fac_building_address.POSTAL_CODE` / `fclt_building_address.POSTAL_CODE` → `zip_usa.ZIP_CODE` (+`STATE_ABBR`, `CITY_NAME`); `fac_building_address.ADDRESS_CITY_ID` is a city token shared by `fclt_building_address(_hist)` for canonical city matching. `ir_institution.STATE` ↔ `zip_usa.STATE_ABBR` links institutions to US states.
