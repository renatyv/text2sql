# Additional Metadata

## Clarified Semantics

- Person identity: `MIT_ID` is a unique person key shared across employees, faculty, students, and directory views (`employee_directory`, `drupal_employee_directory`, `hr_faculty_roster`, `mit_student_directory`, `se_person`, `warehouse_users`, `space_supervisor_usage`), reused as `RESPONSIBLE_FACULTY_MIT_ID` in subject/catalog tables.
- Login alias: `KRB_NAME` / `USERNAME` / `USER_NAME` are the Kerberos handle; `person_auth_area.USER_NAME` and `roles_fin_pa.USERNAME` correspond to it.
- `subject_offered`, `subject_offered_summary`, `subject_summary` are dominated by HAA / HAA.0000 placeholders (Harvard Arts & Sciences cross-registration, `OFFER_SCHOOL_NAME='Non-MIT'`); `subject_offered` has 0 enrollment everywhere.
- `subject_enrollable` holds only Harvard cross-enrollment rows (`OFFER_DEPT_CODE=NIH`, `MASTER_SUBJECT_ID='HAA.0000'`); it is an enrollment staging/holding table, not real MIT offers.
- `cip_with_version` is `cip` exploded per CIP `VERSION`; `CIP_WITH_VERSION_KEY` appends the version digits to `PROGRAM_CODE` (a "program+version" surrogate key).
- CIS catalog tables (`cis_course_catalog`, `course_catalog_subject_offered`, `drupal_course_catalog`) are catalog/section snapshots (not enrollments); `cis_course_catalog` spans academic years ~2002–2008, while `drupal_course_catalog` covers only 9 departments (codes 1–9).
- `fclt_*_hist` are point-in-time facility snapshots keyed by `FISCAL_PERIOD`; `fclt_rooms_hist.FISCAL_PERIOD` is uniformly `201505` (single snapshot present).
- `space_supervisor_usage` is pre-aggregated per supervisor (`DEPT_COUNT`, `NUM_OF_SUPERVISEES`, `SQFT`, `RESEARCH_VOLUME`); `DEPT_NAMES` holds DLC-style codes.
- `libap` materials: `tip_detail` is a bridge from subject-offerings to `tip_material`, with `TIP_MATERIAL_STATUS_KEY` marking required/recommended; `libry` reserves: `library_reserve_matrl_detail` bridges offering, course-instructor, and reserve-catalog rows with `LIBRARY_MATERIAL_STATUS_KEY` (mostly `U`/Unknown).
- Time dimensions differ by domain: `time_day` is day-grain, `time_month.TIME_MONTH_KEY` = `FISCAL_PERIOD` (match `frc_fiscal_periods`), while `academic_terms` is keyed by `TERM_CODE` only.

## Potential Join Strategies

- People: join person/faculty tables on `MIT_ID` (`employee_directory.MIT_ID = se_person.MIT_ID = hr_faculty_roster.MIT_ID = moira_list_detail.MOIRA_LIST_MEMBER_MIT_ID`); link course instructors via `RESPONSIBLE_FACULTY_MIT_ID = MIT_ID`. Caveat: faculty `MIT_ID` is frequently NULL in `subject_offered` and most catalog tables.
- Org units: `fac_organization`/`fclt_organization.HR_ORG_UNIT_ID = hr_org_unit.HR_ORG_UNIT_ID = drupal_employee_directory.HR_ORG_UNIT_ID = zpm_rooms_load.HR_ORG_UNIT_ID` resolves dept names and school hierarchy. Caveat: `HR_ORG_UNIT_ID` is NULL on several raw org rows and ~130/641 `hr_org_unit` rows.
- Dept hierarchy / DLC: `master_dept_hierarchy_links.DLC_KEY = master_dept_hierarchy.DLC_KEY`; with `LINK_TYPE_CODE` `SIS`/`FC`, `LINKED_OBJECT_CODE` matches SIS/space codes, mapping financial DLC codes to academic depts. `DLC_KEY` also links `fclt_organization`, `hr_org_unit`, `space_unit`, `sis_department`, `roles_fin_pa`; use `master_dept_hierarchy` LEVEL_2/3 to roll up to school area.
- Space: `space_detail.FLOOR_KEY = space_floor.FLOOR_KEY`; `space_detail.SPACE_UNIT_KEY = space_unit/space_unit2.SPACE_UNIT_KEY = zpm_rooms_load.SPACE_UNIT_CODE`, and `zpm_rooms_load.HR_ORG_UNIT_ID` supplies dept attribution. Caveat: only ~66 space units exist; thousands of rows share unit `591000`.
- Building+room: `MEET_PLACE` strings in `course_catalog_subject_offered` (e.g. `E51-350`) match `fac_rooms/fclt_rooms.BUILDING_ROOM` and `space_detail.BUILDING_ROOM`; optional/normalized only, since `MEET_PLACE` has many `VIRTUAL`/`TBA`/NULL entries.
- Term mapping: `academic_terms.TERM_CODE = *TERM_CODE` on subject/library/tip tables and `time_day.ACADEMIC_TERM_CODE`; `academic_term_parameter` (`TERM_INDICATOR`, `IS_CURRENT_TERM`) filters current/previous/upcoming. Caveat: catalog `TERM_CODE` is NULL on a minority of rows (e.g. ~1100 in `course_catalog_subject_offered`).
- Subject offering grain: `subject_summary.SUBJECT_SUMMARY_KEY = subject_offered_summary.SUBJECT_SUMMARY_KEY`; `subject_offered_summary.SUBJECT_OFFERED_SUMMARY_KEY = subject_offered.SUBJECT_OFFERED_SUMMARY_KEY`. Use `MASTER_SUBJECT_ID` for cross-section/cluster matching, `SUBJECT_ID + TERM_CODE` for instance-level joins; many instances share a `MASTER_SUBJECT_ID`, so add `SUBJECT_ID`/`SECTION_ID` to avoid fan-out.
- Course catalogs ↔ offerings: `course_catalog_subject_offered`, `cis_course_catalog`, `drupal_course_catalog` join subject tables on `SUBJECT_ID` (+`EFFECTIVE_TERM_CODE`); resolve dept names via `DEPARTMENT_CODE`/`COURSE_NUMBER ↔ sis_subject_code.SUBJECT_CODE` and `sis_department.DEPARTMENT_CODE`.
- TIP materials: `tip_detail.TIP_MATERIAL_KEY = tip_material.TIP_MATERIAL_KEY`, `tip_detail.TIP_SUBJECT_OFFERED_KEY = tip_subject_offered.TIP_SUBJECT_OFFERED_KEY`, status via `TIP_MATERIAL_STATUS_KEY`. Caveat: `ISBN` is NULL on ~22% of `tip_detail` rows (dedupe by ISBN when pricing).
- Library reserves: `library_reserve_matrl_detail.LIBRARY_RESERVE_CATALOG_KEY = library_reserve_catalog.LIBRARY_RESERVE_CATALOG_KEY`; `LIBRARY_SUBJECT_OFFERED_KEY → library_subject_offered`, `LIBRARY_COURSE_INSTRUCTOR_KEY → library_course_instructor`, `LIBRARY_MATERIAL_STATUS_KEY → library_material_status`.
- IAP: `iap_subject_detail` fans out to `iap_subject_person` (`IAP_SUBJECT_PERSON_KEY`), `iap_subject_session` (`IAP_SUBJECT_SESSION_KEY`), `iap_subject_sponsor`, `iap_subject_category`; session times/dates align with `subject_iap_schedule.IAP_DATE/MEET_*` under `TERM_CODE='2021JA'`.
- CIP: `cip.PROGRAM_CODE = cip_with_version.PROGRAM_CODE` (pick one `VERSION` to avoid duplicates); `sis_course_description.CIP_PROGRAM_CODE ↔ cip.PROGRAM_CODE` for degree-program classification.
- Moira lists: `moira_list.MOIRA_LIST_KEY = moira_list_detail.MOIRA_LIST_KEY`, `MOIRA_LIST_OWNER_KEY → moira_list_owner`, `MOIRA_LIST_MEMBER_MIT_ID →` person `MIT_ID` for list-membership analysis.
- Time/facility: join `fclt_*_hist` and financial tables to `time_month` on `FISCAL_PERIOD`; academic offers join `time_day` via `ACADEMIC_TERM_CODE = TERM_CODE`. `academic_terms` carries no `FISCAL_PERIOD`, so fiscal-domain joins go through the time dimensions instead.
